## Runtime changes

Common client-visible actor state, cube squish history, panda counters/blends, world day/moon observations and player facing/level now have providers. Query utilities are available through Molang.Context regardless of actor/particle/attachable consumer. Numeric slider settings execute. Axis indices reject missing, fractional, non-finite and out-of-range arguments.

Rendered attachable items have their own durability/enchantment/stackability/tag snapshots instead of implicitly reading the owner's main hand. Equipment snapshots include body armor damage and hand-specific remaining use time. Missing known slots are empty; unknown slots remain errors. Block-neighbor tags use the containing block origin, unlike actor-relative tags.

Particle definitions can observe live per-effect emitter/particle counts and actual emitter-root camera distance, including unbound effects. Actor queries continue through the owning actor snapshot; child variable scopes remain independent. Particle query contexts no longer fabricate universal zero in an actor-less provider. Unsupported actor queries still lack a value; entity rendering retains its existing content-error fallback.

`MolangQueryProvider` represents unavailable data as Optional.empty, distinct from present false/zero/string results. `NativeMolangQueries.register` supplies per-actor extraction snapshots, forwarded through ordinary entity contexts to render controllers, animations, owner-backed attachables and particle effects. Factories must supply observations, not execute gameplay or load chunks. Nothing here synchronizes BP properties or implements server logic.

## Remaining gaps (not all BP dependencies)

- Frame statistics, bone AABB/orientation matrix, complete locator/default pivot contexts, surface particle texture/color sampling, full inventory/cooldown/armor enums, platform/input and several vanilla-specific actor/action states still lack providers. The inventory below is authoritative for this pass's limited support claims.
- Version availability/removal semantics are recorded, **not enforced**. Deprecated queries may still execute regardless of min_engine_version.
- Four documented BP/server-only queries: anger_level, had_component_group, scoreboard, server_memory_tier. They are outside RP gameplay completeness and remain unavailable; the extension interface is not an implementation of their data.
- Exact normalized-use-time convention, player world-origin offset, movement sampling and remote state availability need Bedrock comparisons. Existing hurt_time unit inconsistency, UUID-derived skin_id, visibility constants and splash-water contact approximation remain unresolved.
- Per-effect emitter count can omit the constructing emitter during startup expressions. Total-world counts including Java particles are unsupported. Offscreen actor/locator snapshots may be stale.
- Generic block/item-definition and placement-event contexts are not added by the rendered-attachable item adapter. Custom tags/properties require real authoritative sources.
- Unit coverage is not yet per-supported-contract exhaustive. Full cross-context, version, event-chain and positive actor-state parity remains open.
