# Particle compatibility and validation pass

Date: 2026-10-12. Scope: the existing audit's **40 particle contracts** (11 capability contracts + 29 component contracts), plus controller `bind_to_actor`. This is not 40 full-spec certifications. Official references are pinned in each row below; no extra count is awarded for parsing a JSON field.

## Results and counting

- Functional breadth: **38/40 → 40/40 (100%)**. Previously missing event sound and log paths now execute.
- Targeted production-runtime/numerical subset validation: **6/40 → 40/40 (100%)**. This means at least one relevant behavioral subset per row, not every subfield or combination.
- Substantially complete/cross-engine certified: **0/40**. Exact full-contract completeness remains unknown. 39 contracts are Partial; log dispatch is Implemented but not content-log-equivalence certified.
- Full isolated unit suite: **277 tests passed, zero failures/errors/skips**, including the read-only Actions & Stuff reference-pack checks. No instance pack files were modified.
- Full real-client/integrated-server suite passed with Actions & Stuff 1.12: particle fixtures plus existing player, animation, held-item, geometry, material, pack priority/configuration and other regression checks. Final expanded fixture/reference run: **2m 24s, passed**. Dedicated material/moving-trail run: **2m 17s, passed**, including allay emitter history, sulfur material-switch lifecycle, repeated trapdoor confetti and chained ground emitters. Snapshot counts: allay 19 particles/4 emitters; sulfur 80/4. Counts vary by timing and are not visual certification.
- Pinned Mojang flame/smoke definitions run as standalone and entity-animation-triggered effects. Only identifiers and fixture textures are remapped. Client state assertions verify child expiration dispatch, isolated startup values, binding/locator movement, atlas stitching, vanilla override and fire suppression/stop. This is independent of Actions & Stuff's particle authoring.
- Fixture, allay and sulfur screenshots inspected: particles render and colored sulfur confetti is visible. These captures do not certify the ground smear/ribbon trail appearance. They are not Bedrock comparisons, material alpha-threshold tests, complete facing-mode visual checks or audible verification.

## Runtime repairs

Child `pre_effect_expression` now starts in a fresh child-emitter context; event expressions execute in the firing emitter, not an accidental copied particle scope. Child `particle_with_velocity` receives the spawning particle's world velocity. Startup scripts no longer mutate the actor just because a particle controller or animation emitted them.

Controller binding survives aliases and start/stop dispatch. Unbound emitters snapshot locator world position; bound emitters follow actor/locator frames. Managed controller emitters deduplicate without suppressing independent animation bursts. Child manual emissions reuse their target where appropriate and respect caps.

Sound events dispatch positional Java sound instances, resolving imported definitions and individual level-event aliases, with mapped vanilla fallbacks. Event log messages include effect and world position. String-form sound references now retain level-event volume/pitch gains.

Emitter scheduling now uses documented ten-second lifetime defaults, per-loop duration/random evaluation, manual/steady caps, fractional rate credit, sorted timeline endpoints and distance events. Particle per-render initialization executes during actual extraction. All eleven billboard modes have separate finite basis calculations; heading thresholds retain the previous direction. Shape sampling, world/local velocity conversion, world-axis kill-plane crossing, absolute collision drag and collision event object form are corrected.

The shared headless runtime is the production scheduler, not a second test implementation. Motion/appearance helpers are consumed by the real client. Tests replace only world/audio/particle sinks where Minecraft is unavailable headlessly; generated JSON alone is not runtime validation.

## Remaining limitations / next gates

1. Local-position particles still bypass Java collision resolution. Add moving/rotating local-space collision fixtures before claiming this combination.
2. Actor queries/locator frames are refreshed by rendering; offscreen actor effects do not have an independent complete pose update contract. Entity removal/attachment lifetime combinations require more tests.
3. Inherited velocity is added to authored initial speed after world/local conversion. Verify exact additive semantics with a Bedrock-side trace; no cross-engine oracle was available in this pass.
4. Out-of-atlas UVs crop the quad, not arbitrary wrap. Java cutout alpha threshold and blend sorting may differ from Bedrock. Custom material names fall back to blend, not arbitrary shader execution.
5. Sound event execution exists, but context-dependent block/entity level-event selection, categories, attenuation, unsupported mappings and audible comparison remain partial.
6. All facing branches have numerical tests; all-mode visual handedness, asymmetric curves, nonuniform moving transforms, exact collision/contact ordering, particle/emitter expiry combinations and shape distributions need differential captures.
7. Intentional safety budgets: 8,192 live particles, 512 emitters, 256 per-emitter spawn/event crossings per update, bounded recursive events and a 12,000-tick particle lifetime cap. These can truncate pathological or very long authored effects.
8. Existing Java effects are retained when there is no imported definition/mapping or a higher-priority Java resource owns the particle. Mappings are curated, not an implementation of BP gameplay or every Bedrock level event.
9. The full Actions & Stuff scene reports missing `attachable/main_hand/lead_hold` for effects `oreville_ans:bvivod` and `oreville_ans:xsjhvb`. These locator-dependent effects are not silently counted as working. The allay reference definition also reads triggering-event temporaries in a child startup script; the official contract explicitly forbids reading the spawning emitter's Molang data. Fresh context behavior is retained; exact pack-author intent needs independent Bedrock comparison, not a pack-specific inheritance hack.

The pack corpus run is a regression stress check, not a promise that every Actions & Stuff effect is visually identical. No pack-name or obfuscated-effect-specific production workaround was added.

Earlier dedicated runs failed on an assertion made before teleport packets/rendered query snapshots caught up, then on test reflection looking only for fields declared directly on the emitter subclass. The final tests retain the history/material/color assertions, wait three ticks for synchronization, and use inherited public-field lookup. No production state-reset workaround was added for those harness failures. Runtime sound/log execution appears in the fixture trace; audible parity remains unverified.
